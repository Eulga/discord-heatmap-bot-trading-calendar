# 구현 맵

이 저장소는 Discord bot을 담당한다.

## 전체 책임

- 히트맵 전송
- 관심종목 급등락 알림 전송
- 뉴스 속보 전송
- 뉴스 피드백 입력을 받아 Collector에 저장 요청
- 시장 리포트와 관심종목 리포트 전송
- 어닝/경제 일정 알림 전송
- 디스코드 로그인 버튼과 토큰 발급
- 대시보드 접근용 사용자 등록 버튼
- 관심종목 역할 생성, 동기화, 부여, 정리
- slash command 처리
- 전송 성공/실패 로그 저장

## 책임이 아닌 것

- 시세, 뉴스, 공시, 어닝, ETF, 매크로 데이터 수집
- 투자 리포트 본문 생성
- 웹 로그인 세션 유지
- 웹 권한 판단
- 관심종목 저장 원본 관리

위 데이터와 판단은 각각 `StockDataController`와 `Stock-Dashboard`가 맡는다.

## 시스템별 역할

| 시스템 | 담당 |
| --- | --- |
| Discord bot | Discord 채널/스레드/역할/명령어 처리 |
| Stock-Dashboard | 로그인 토큰 검증, 사용자 DB, 리포트 저장, delivery 후보 제공 |
| StockDataController | 시장 데이터, 뉴스, 일정, 알림 후보 생성 |
| Bot PostgreSQL | 봇 자체 상태와 Discord delivery metadata |

## 주요 코드 위치

| 경로 | 담당 |
| --- | --- |
| `bot/app/` | 앱 시작, 설정, command sync |
| `bot/features/` | 뉴스, 알림, 리포트, 로그인, 역할 등 기능 |
| `bot/forum/` | 포럼/스레드 상태 저장과 갱신 |
| `bot/markets/` | 히트맵 캡처와 시장 helper |
| `bot/intel/` | 외부 provider/registry 관련 기존 기능 |
| `scripts/` | 개발 환경, 검증, 운영 보조 스크립트 |
| `tests/` | 단위/통합 테스트 |

## 디스코드 전송 흐름

1. Dashboard나 Collector가 전송 후보를 저장한다.
2. Bot scheduler가 주기적으로 후보를 읽는다.
3. Bot이 Discord 채널 또는 스레드에 embed/card 형태로 전송한다.
4. 성공/실패 결과를 저장한다.
5. 운영 화면은 저장된 결과를 보여준다.

## 관심종목 알림

관심종목 알림은 같은 날짜의 스레드 하나를 재사용한다.
한 종목이 여러 기준을 넘더라도 같은 일자 스레드 안에 묶어 보낸다.

종목 역할이 있으면 해당 역할을 멘션한다.
역할은 웹 관심종목을 기준으로 동기화하며, 삭제된 관심종목 역할은 미사용 표시 또는 정리 명령으로 관리한다.

## 뉴스 전송

뉴스는 원문 전체를 길게 붙이는 대신 아래 기준을 따른다.

- 핵심 제목
- 짧은 요약
- 투자 판단에 필요한 포인트
- 원문 링크

단순 지수 등락 반복 뉴스는 보내지 않는 방향이 기본이다.
뉴스 카드에 붙은 피드백 선택 메뉴는 Bot이 입력만 받고, 저장은 StockDataController API에 위임한다.

## 리포트 전송

시장 리포트와 관심종목 리포트는 분리해서 전송한다.

- 시장 리포트: 시장, 금리, 환율, 유가, 매크로, 수급 중심
- 관심종목 리포트: 보유/관망/매수 후보 판단, 리스크, R/R 중심

본문이 길면 디스코드에는 요약과 전체보기 링크를 우선한다.

## 로그인 버튼

로그인 채널에는 등록 버튼과 로그인 버튼을 둔다.

- 등록 버튼: Discord ID 기준으로 웹 계정 생성 또는 연결
- 로그인 버튼: 1회용 토큰을 만들고 대시보드 입장 링크 제공

개인에게만 보이는 응답은 일정 시간이 지나면 삭제한다.

## 운영 주의사항

- Discord 권한 부족은 전송 실패로 기록하고 다음 전송까지 bot 전체를 멈추지 않는다.
- forum/thread 권한은 서버 설정과 bot role 권한을 같이 확인한다.
- Dashboard URL은 환경변수에서 읽는다. 하드코딩하지 않는다.
- 공개 URL을 바꿨으면 bot만 재기동해도 로그인 링크가 갱신된다.
